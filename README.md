# Atexar / Genesis — expanded website

Updated 10 October 2026. Canonical domain: https://atexar.in
Contact: Vedanshdubey@atexar.in

## What is included

18 content pages plus a custom 404 page. The site retains the existing Atexar logo, founder photograph, chrome sculpture, dark/cream/lime palette, and founder motto. It adds a procedural Milky Way background, interactive capability diagram, animated vector roadmap, service details, engagement plans, and editorial notes.

Main pages: Home, Genesis, Solutions, SaaS Marketing, Sales Boosting, Autonomous Virtual Assistance, Unified Intelligence, How We Work, Plans, Roadmap, About, FAQ, Contact, Field Notes, three articles, and Privacy.

Market thesis: disconnected marketing, sales, and operations lose context at handoffs, forcing people to repeat work. Atexar aims to connect context, ownership, and the next action. This is a positioning thesis to validate through discovery and pilots, not a quantified market claim or claim of unique invention.

Roadmap stages and engagement plans are proposals. The website does not present future software as a shipped self-serve product, fabricate client results, or promise launch dates.

## Update an existing Cloudflare Pages project

For a Direct Upload project, open Workers & Pages, select the existing project, and choose Create a new deployment. Upload this ZIP or its extracted folder with index.html at the root. Choose production when ready to replace the live version. Keep all assets and subdirectories.

For a Git-connected project, extract and commit the files into the repository's configured output directory. Do not commit just the ZIP. No frontend build is required: Framework preset None; build command can be left blank (or exit 0); output directory should point at this folder, e.g. / if these files occupy the repository root.

This is a static site with a small Cloudflare Pages advanced-mode _worker.js for hostname redirects. Cloudflare supports _worker.js in dashboard drag-and-drop uploads. No npm installation, API key, database, or external server is required. Worker requests are subject to the account's Pages Functions/Workers limits. _routes.json avoids invoking it for the listed static assets.

If your existing hosting is Workers Static Assets rather than Pages, do not upload _worker.js expecting Pages behavior. Use a Pages project, or adapt the worker binding and deployment configuration to the existing Workers project first.

## Domain and subdomains — activation still required

The files alone do not create DNS records. In the same Pages project, open Custom domains and add each domain below. Follow Cloudflare's generated DNS setup and wait for each to show Active:

| Domain | Behavior after attachment |
| --- | --- |
| atexar.in | Main website |
| www.atexar.in | Permanent redirect to atexar.in, preserving the path |
| genesis.atexar.in | Root redirects to atexar.in/genesis/ |
| solutions.atexar.in | Root redirects to atexar.in/solutions/ |
| insights.atexar.in | Root redirects to atexar.in/insights/ |

The three named subdomains are convenient entry points, not separate software apps. Their non-root paths redirect to the same path on atexar.in. Query strings are preserved. Main navigation uses the working canonical paths so it does not depend on unactivated subdomains.

For an apex domain, Cloudflare Pages requires the domain's zone/nameservers on Cloudflare. For externally managed subdomain DNS, use the CNAME target generated by the actual Pages project, never a guessed project name. Add the domain to Pages before adding the CNAME. Preserve all existing email MX, SPF, DKIM, and DMARC records. Do not change mail routing to deploy this website.

After deployment check the home page, a nested service page, the contact draft, the mobile menu, and each activated domain. Keep the previous deployment available for rollback.

## Contact behavior

The contact form prepares a mailto draft in the visitor's email app. It does not send messages, submit to a database, or imply a booking. A direct email link and copy button are also provided. With JavaScript disabled, use the direct email link. This first version deliberately needs no email backend or credentials.

## Motion and accessibility

Galaxy and sculpture rendering are capped at approximately 25 frames per second. The dense starfield is pre-rendered and reused. The sculpture stops rendering offscreen; ambient motion stops in hidden tabs. Pause motion controls both CSS and canvas animations, remembers the preference, and respects the operating-system reduced-motion setting. The timeline buttons, mobile menu, disclosures, and form use native keyboard controls. Content remains available without animations.

## Editing

Each page has its own index.html in its directory. Shared appearance lives in styles.css, shared behavior in script.js, and sculpture rendering in sculpture.js. Keep absolute /assets/... URLs when deploying at the domain root. Opening files directly with file:// will not resolve root-relative links; use a local HTTP server rooted in this folder for development.

The supplied portrait bytes are unchanged. CSS creates the circular crop and monochrome treatment. The existing SVG logo is retained with a tighter viewBox to avoid excess blank space. Google Fonts has system fallbacks.
